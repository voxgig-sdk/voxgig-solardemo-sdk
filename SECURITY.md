# Security

## Reporting a vulnerability

Email **security@voxgig.com**. Please do not open a public issue for a
suspected vulnerability.

Include what you need to make it reproducible: the affected artifact and
version, the request or call that triggers it, and what you observed
versus what you expected.

## What is published from this repository

Two artifacts are released, and only these are in scope as *published*
software:

| Artifact | Registry | Version |
| --- | --- | --- |
| `@voxgig-sdk/voxgig-solardemo` | npm | see `ts/package.json` |
| `github.com/voxgig-sdk/voxgig-solardemo-sdk/go` | Go module proxy | see `go/VERSION` |

Both are generated by [`@voxgig/sdkgen`](https://github.com/voxgig/sdkgen)
from `.sdk/`. A defect in generated SDK code is usually a defect in the
generator or the model, and the fix belongs there — see
[`AGENTS.md`](AGENTS.md).

## `app/` is a test server, not a product

`app/` exists so the SDKs have something to talk to. It is **not**
published, not intended for deployment, and deliberately omits things
production services need:

- **No authentication or authorization.** The OpenAPI definition declares
  no `securitySchemes`, and the server has no auth middleware. The SDKs
  carry apikey plumbing that this server never exercises.
- **`GET /debug` returns the entire store**, unauthenticated and absent
  from the OpenAPI definition. Harmless on the default `localhost` bind;
  a data-disclosure endpoint the moment `HOST=0.0.0.0` is set.
- **State is in memory**, seeded from a JSON file at start, and lost on
  restart.
- **Field validation is shape-level only** — an empty `kind` or a
  negative `diameter` is accepted.

If you deploy it anyway, none of the above is a vulnerability report; it
is the documented design. Reports about `app/` are welcome where the
behaviour departs from what this file and the OpenAPI definition
describe.

## Supply chain

- Every GitHub Action is pinned to a full-length commit SHA, and the
  repository's Actions policy rejects tag references outright.
- npm publishing uses **OIDC trusted publishing** — there is no
  `NPM_TOKEN` secret in this repository. See
  [`design/PUBLISHING.md`](design/PUBLISHING.md).
- `ts/dist` and `ts/dist-test` are committed so the repository can be
  cloned and tested without a build step. They are generated output:
  treat a discrepancy between them and `ts/src` as a bug, and see the
  `Generate and check for drift` CI job, which enforces exactly that for
  `ts/` and `go/`.
